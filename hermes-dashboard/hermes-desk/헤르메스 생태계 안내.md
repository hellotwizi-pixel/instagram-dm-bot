# 헤르메스 생태계

자비스 관제실을 참고한 홀로그램 디자인. 미미르는 정교한 반투명 뇌 이미지와 실제 입체 회전 아크, 프로젝트는 표면 질감·외곽광을 갖춘 행성과 투사대로 표현한다. 커서를 올리면 행성이 떠오르고, 누르면 확대된다.

기존 `Hermes Desk 열기.command`로 실행. 첫 화면은 미미르와 여섯 프로젝트가 연결된 입체 생태계. 켜져 있는 화면은 새로고침하면 된다.

## 화면에서 보는 것

- **위쪽 미미르**: 실제 쌓인 자료와 정리된 지식. 회전하는 푸른 아크와 신경망.
- **주변 데이터 연결**: Gmail, Drive, 문서, 사진 판독, 캘린더, 인스타, 사이트 실적, Slack, AI Council, Claude Code, 헤르메스 대화, 에이전트 작업, 프로젝트 지식을 각각 표시. GPT 대화는 헤르메스 기록에서 확인한 부분만 따로 보여주고 전체에 중복 합산하지 않는다. 카카오톡·직접 자료의 별도 적재 기록도 구분. 새 원천은 자동 추가.
- **아래 여섯 행성**: ACE 인도어골프, 바베큐국립공원, 하하팩토리, 디토크, DMmate, AI-OS 관리.
- **행성 안의 부서**: 실제 배정된 업무와 설치된 담당. 행성 → 부서 → 원래 요청 → 보고와 결과 파일 순서로 확인.
- **전체 공간**: 데이터를 읽고 업무를 분담하는 헤르메스.

## 조작

- 행성·부서·미미르·데이터 이름 또는 연결선을 누르면 확대와 상세 창.
- `데이터 연결`: 모든 원천의 수집 내용과 건수. 항목을 누르면 본문·첨부·보류·실패 내역, 경로, 수집 예약, 마지막 적재 시각.
- `문제 있는 곳`: 확인할 연결만 강조. 원인과 해당 프로젝트로 이동.
- `결과 보관함`: 연결된 중간·최종 결과. 원래 업무 보고로 이동해 파일 확인.
- `전체 보기` 또는 Esc: 처음 위치로 복귀.
- 빈 공간을 드래그하면 회전. ＋/−로 확대·축소.
- `⛶`: 전체 화면. `Ⅱ`: 움직임 멈춤.
- `업무 보고`와 `에이전트 조직도`로 기존 화면 이동. 업무 보고 왼쪽 메뉴에서 기존 업무 마을도 열 수 있음.

## 색과 움직임의 의미

| 표현 | 의미 |
| --- | --- |
| 굵은 파란 선과 흐르는 빛 | 수집 연결 유지. 최근 수집 실행·적재 기록 기준 |
| 빨간 선 | 기록에 남은 업무 차단·실패 또는 기억 처리 장치의 확인된 오류 |
| 노란 선 | 진행 소식이 오래됐거나 새 자료가 오래 없는 곳 |
| 회색 점선 | 업무 배정·자료 적재 기록이 없거나 상태 미확인 |
| 업무 배달부 이동 | 새로 관찰한 배정·시작·완료 기록 |
| 데이터 입자 이동 | 새 적재 수 증가 또는 업무와 정확히 연결된 회사 기억 조회 |

반복되는 파란 빛은 연결 유지 표시이며, 특정 파일의 실시간 전송량·속도를 뜻하지 않는다. 별·아크 회전은 배경 효과. 업무 완료 비율은 **등록된 세부 업무 개수** 기준이며, 시간·품질·Slack 보고 전달 성공을 추정하지 않는다.

## 흐름 체험

`흐름 체험`을 누르면 약 34초 동안 가상 요청이 프로젝트로 전달되고, 부서 배정 → 미미르 조회 → 검토 중 막힘 → 다시 진행 → 완료로 이어진다. 체험 중에는 가상 업무 표시가 계속 보이며, 실제 Slack 메시지·작업 상태·회사 자료는 변경하지 않는다. `실제로 돌아가기`로 실제 기록을 다시 표시한다.

## 반영 범위

실행 기록은 기존 3초 확인, Slack 요청·보고는 기존 10초 확인을 사용한다. 미미르 자료 집계는 8초마다 조회하며 서버에서 최대 12초 재사용한다. 자료 건수와 마지막 적재 시각을 읽으며 외부 서비스 자체의 실시간 장애 진단은 아니다.

미미르 조회 선은 관찰된 세션·업무 번호와 명시적인 회사 기억 조회 도구 호출이 정확히 연결될 때 표시한다. 최근 1시간, 최대 8개 프로필·40개 세션 묶음·세션당 100개 호출 메시지 범위를 확인한다. 기록되지 않은 호출, 다른 호출 방식, 여러 업무가 섞여 소속을 확정할 수 없는 조회는 임의의 행성에 붙이지 않는다. 따라서 모든 에이전트의 모든 정보 조회가 보이는 상태는 아니다.

화면을 처음 열었을 때의 과거 배정 기록은 새 움직임으로 재생하지 않는다. 연결 실패·오래된 응답은 미확인으로 바뀌고 해당 이동을 멈춘다. 요청자나 프로젝트가 연결되지 않은 업무를 추측으로 여섯 행성에 넣지 않는다.


## 데이터 표시 개선 (2026-09-27)

기존 8개 묶음을 없애고 실제 원천을 개별 표시한다. 현재 저장 기록은 13종류이며 화면 수는 미적재·경로 확인 항목 및 GPT 파생 보기를 포함하므로 13개보다 많다. 원천 이름·건수는 저장소에서 자동 갱신한다. 새 이름이 발견되면 원천은 즉시 추가되며, 친절한 기능 설명은 확인 후 보완한다.

- **Claude Code**: 작업 대화 파일에서 사람의 요청과 작업 결론 수집. 기록 수는 고유 대화 수와 다를 수 있음.
- **GPT 대화**: 미미르에 저장된 Hermes 답변 번호를 실제 모델 기록과 대조해 확인. 텔레그램·터미널 건수에 이미 포함. ChatGPT 앱의 대화를 직접 가져오는 별도 수집 경로는 아직 확인 중.
- **메일·문서**: 전체 수집 기록과 내용 저장 건수를 구분. 보류·실패·글자 없음은 내용 저장에서 제외.
- **Drive**: 문서·사진 처리 경로를 포함한 전체 누적 기록 표시. 상세에서 문서·사진·파일 발견을 나눠 확인. 문서·사진 카드와 겹치는 수는 미미르 전체 합계에 한 번만 반영.
- **직접 자료·링크**: 다른 원천에 들어갔을 수 있으므로 별도 원천의 기록 부재를 전체 자료 부재로 해석하지 않음.
- **지식 정리**: 자료에서 회사 지식을 뽑아 검색·기억에 활용. 수집 건수는 기반 LLM의 가중치 재학습 완료를 뜻하지 않음.

뇌 그래픽의 생성 방식과 최종 프롬프트는 [미미르 그래픽 제작기록](미미르%20그래픽%20제작기록.md)에 보관.


## 전체 누적량과 연결 흐름 (2026-09-27)

- 모든 숫자는 현재 미미르에 저장된 **전체 기간 누적 기록 수**. 이번 갱신의 증가량이 아님. 0건도 숫자로 표시하며, 확인하지 못한 값만 —로 표시.
- Drive 숫자는 원천 drive의 파일 발견뿐 아니라 document/image의 드라이브 문서·사진 기록까지 포함. 개별 카드와 겹치므로 전체 합계에 다시 더하지 않음.
- 수집 연결이 유지되는 원천은 기존보다 약 3.6배 굵은 파란 선과 미미르 방향으로 반복되는 빛으로 표현.
- 연결 표시는 저장된 자료·최근 수집 실행을 기준으로 판별. Gmail은 별도 수집 예약과 최근 확인 시각 사용. 개별 서비스의 실시간 네트워크 속도 측정은 아님.
- 일시 중지, 오래된 확인, 조회 실패 시 반복 흐름을 멈춤. 마지막으로 확인한 누적 숫자는 지우지 않음.
- 움직임 멈춤 버튼과 기기 움직임 줄이기 설정을 따름. 애니메이션은 기록을 추가하거나 누적 숫자를 변경하지 않음.
