# Hermes Desk 보고체계 기준

최우선 목표: **실사용자가 보기에 최적의 보고체계.** 사용자는 비개발자다. 내부 실행 구조가 복잡해도 화면은 다음 다섯 질문에 답해야 한다.

| 사용자 질문 | 화면이 보여줄 내용 |
| --- | --- |
| 내가 뭘 맡겼지? | 요청 한 줄 요약, 요청자, 원래 대화 |
| 누가 나눠 맡아 어디까지 했지? | 알아보기 쉬운 담당 역할, 맡은 업무, 연결된 앞 업무, 현재 상태, 멈춘 이유 |
| 다른 사람들은 뭘 시켰지? | 팀 전체 요청 목록, 요청자 필터 |
| 프로젝트마다 어떻게 되고 있지? | 프로젝트별 요청·진행·대기·확인 필요·완료, 연결된 결과 |
| 어떻게 끝났고 결과는 어디 있지? | 완료 또는 중간 결과 구분, 담당별 보고, 결과 파일, Slack 대화 |

## 적용한 화면

- 첫 화면: 내가 맡긴 일 / 팀 전체 / 프로젝트별 / 결과물.
- 내가 맡긴 일: Slack에 기록된 요청자 선택. 선택값은 이 기기에 저장. 로그인이나 권한 분리 기능은 아니다.
- 업무 한 건: 짧은 제목 → 지금 상황 → 담당별 분담 → 보고와 결과 파일.
- 모델, 내부 에이전트 이름, 작업 번호, 오류 원문은 관리자 점검 안에 배치.
- 새 기록은 10초마다 반영. 새 요청·작업·프로젝트·첨부 파일도 기록에 있으면 반영.
- 기존 주요 요청 8건의 제목은 실제 내용을 검토해 짧게 정리. 원문이나 작업 구성이 바뀌면 검토 제목 사용을 중단하고 최신 업무 제목으로 표시하여 오래된 요약을 방지.
- 등록된 첨부 파일은 화면에서 내려받기. 완료하지 않은 업무의 첨부 파일도 상태와 함께 표시. 파일이 많으면 펼쳐 보기.

## 사실을 구분하는 원칙

- 요청자가 없으면 요청자 미확인. 작업 카드를 만든 에이전트를 사람인 요청자로 표시하지 않는다.
- 프로젝트는 실제 채널 연결 또는 등록된 프로젝트로 묶는다. 제목에 이름이 비슷하다고 자동 확정하지 않는다.
- 한 Slack 대화에 이어진 후속 요청은 현재 하나로 표시. 각각을 독립 요청으로 분리했다고 주장하지 않는다.
- 작업 완료, 결과 품질 검증, Slack에 보고가 전달된 사실을 구분한다.
- 앞 작업 대기, 실행 중 문제, 추가 권한 필요를 구분한다. 모든 멈춤을 사용자 승인 대기로 표현하지 않는다.
- 결과 파일은 작업에 등록된 파일이다. 같은 이름의 파일도 연결 업무의 상태·등록 시각을 함께 표시한다.
- 캐릭터와 효과는 실제 진행을 이해하는 보조 표현이다. 진행률이나 성공을 임의로 만들지 않는다.

## 남아 있는 보고체계 과제

2026-09-26 확인: 화면에 연결된 요청 19건, 파일 64개. 요청 중 11건은 작업별 진행 연결이 없고, 요청자 미확인 6건. 원래 대화에 연결되지 않은 이전 업무 256개는 요청 집계에서 제외되어 있다. 이 숫자는 이후 기록에 따라 바뀐다.

1. 이전 업무의 원래 요청·요청자·프로젝트 연결 복구. 근거가 없는 연결은 보류.
2. 새 요청을 받을 때 요청자·프로젝트·요청 한 줄·원래 대화를 처음부터 빠짐없이 남기는 과정 검증.
3. 같은 대화의 후속 요청을 구분하고 작업의 중복 분담 방지 검증.
4. 진행 소식과 멈춘 이유, 다음 필요한 행동이 사용자 언어로 남도록 보고 내용 개선.
5. 완료 시 최종 결과와 중간 파일, 최신 버전을 구분하는 결과 정리 개선.
6. 실제 Slack 재시험으로 접수 → 분담 → 진행 보고 → 완료 → 결과 접근을 확인. 이전 허용 시험 1건은 이미 사용했고, 두 번째 시험은 아직 승인되지 않았다.

이번 화면 개편만으로 Slack 운영 문제 전체가 해결된 것은 아니다. 화면과 실제 실행·보고를 같은 기준으로 완성해 나간다.
